# Git 备份与同步

打开尚无 Git 仓库的独立文档库时，Quiet.md 会初始化本地 `main` 分支并写入 Git LFS 和忽略规则。提交和推送由用户手动发起。作者、远端和自动拉取间隔在「设置 → Git 备份与同步」配置，日常操作及对比在侧栏「Git 变更」中进行。单篇文章的提交可在「… → 版本历史」查看。

Git 由 `git2` 和编入应用的 libgit2 实现；图片和附件由应用实现 Git LFS 指针、对象缓存与 Batch / Basic HTTP 协议。运行时无需安装 Git、Git LFS 或命令行凭据助手，也不执行仓库钩子。

## 使用

1. 如需设置提交作者，填写名称和邮箱。需要同步时另填远端仓库地址，然后点击「保存配置」。
2. HTTPS 远端认证填写用户名和访问令牌。令牌显示为掩码，仅在本次窗口会话中保留，不写进笔记库、JSON 元数据或 Git 配置。也可通过 `QUIET_MD_GIT_USERNAME` / `QUIET_MD_GIT_TOKEN` 提供。
3. 写完文章后，打开侧栏「Git 变更」，确认提交说明并点击「提交本地变更」或工具栏的提交按钮；提交说明默认填写当天日期。操作前保存所有窗口中的文章。有可见的已暂存变更时只提交暂存区，否则提交整个文档库。
4. 「推送」先上传所提交历史引用的 LFS 对象，成功后再推送 Git 引用。「拉取」只允许快进；本地有未提交改动或历史已经分叉时停止，不自动丢弃或合并文章。
5. 在另一台电脑填写远端后使用「克隆到空文件夹…」，完成后按应用原有的切换文档库流程打开。克隆会读取远端默认分支，并下载文章历史引用的 LFS 对象。

「自动拉取」默认关闭。配置远端后，可选择每 1、5、15、30 或 60 分钟拉取一次，再点击「保存配置」。应用运行时执行快进拉取。本地有未提交变更或窗口中有未保存改动时，应用会跳过本次，按所选间隔再试。拉取失败会在 Git 设置中显示。自动拉取使用最近一次保存 Git 配置时填写的会话凭据。重启后可通过环境变量提供凭据，或重新填写并保存配置。

每个文档库的 `.quiet/git.json` 保存 Quiet.md 使用的 Git 作者、远端、LFS 地址、SSH 私钥路径、LFS CA 路径和自动拉取间隔。首次打开旧文档库时，应用从已有 Git 配置导入作者和远端等设置。点「保存配置」时，会同时更新 `.git/config` 中供系统 Git 和 Git LFS 使用的配置项。应用内的设置和同步操作以 `.quiet/git.json` 为准，当前分支仍从 Git 的 `HEAD` 读取。

远端支持 HTTPS、SSH（`ssh://git@host:2222/team/notes.git` 或 `git@host:team/notes.git`）和独立本地仓库路径（也支持 `file://`）；回环地址的 HTTP 可用于本地服务。当前不支持系统凭据助手、自动提交或分叉历史合并。可选 LFS 地址用于服务商单独部署的 LFS 端点。没有上传动作的 LFS 对象表示服务器已持有；提供 verify 动作时，上传后执行确认。

## SSH 私钥与 LFS CA

设置中的「SSH 私钥路径」可填写自定义私钥（支持 `~/`），保存时也写入本机仓库的 `quiet.sshKey`。也可通过 `QUIET_MD_GIT_SSH_KEY` 提供路径，两处都为空时使用 SSH agent。加密私钥的密码在「私钥密码」中填写，或通过 `QUIET_MD_GIT_SSH_PASSPHRASE` 提供；密码与访问令牌一样只在内存中保留。SSH URL 中的用户名优先，未指定时使用 `git`。

Git 与 LFS 的 SSH 连接都会核对 `~/.ssh/known_hosts`，不自动接受未知或已变更的主机密钥。使用非标准端口时，记录为 `[host]:2222`。可用 `QUIET_MD_GIT_KNOWN_HOSTS` 指定其他已核对的 known_hosts 文件。目前不读取 `~/.ssh/config` 的 Host 别名、IdentityFile 或代理配置，请在远端地址中填写实际主机与端口。

SSH 仓库的 LFS 默认通过 SSH 执行远端 `git-lfs-authenticate <仓库路径> upload|download`，再使用服务器返回的 HTTPS 地址与临时认证头进行 Batch 请求；SSH 端口不会当成 HTTPS 端口。服务器明确表示命令不存在时，回退到推导的 HTTPS LFS 地址，可填写访问令牌。设置显式 LFS 地址时，使用该地址与访问令牌认证。

LFS 的自签证书使用 PEM CA 文件，保持证书链与主机名校验。设置中的「LFS CA 证书」用于 LFS 地址的主机和 HTTPS 端口。保存时，应用在 `.git/config` 中同时写入带尾部 `/` 和不带尾部 `/` 的 HTTP 小节。如果 Batch、上传、下载或 verify 地址使用其他主机或端口，应用仍会按该请求地址匹配 Git 配置中的 `http.sslCAInfo` / `http.<URL>.sslCAInfo`。

例如下面的本机配置可使用 SSH 2222 端口同步 Git，并让 LFS 信任该服务的 CA：

```gitconfig
[remote "origin"]
    url = ssh://git@git.example.com:2222/you/notebook.git
    fetch = +refs/heads/*:refs/remotes/origin/*
[quiet]
    sshKey = /path/to/your/private_key
[http "https://git.example.com"]
    sslCAInfo = /path/to/ca.crt
[http "https://git.example.com/"]
    sslCAInfo = /path/to/ca.crt
```

私钥、密码和 CA 文件本身不会复制进文档库或提交；`.git/config` 只保存路径。原有的 LFS filter 配置保留，应用仍使用内置 LFS，不运行这些命令。

## 查看工作区变更

启用后，侧栏「Git 变更」打开独立面板。左侧列出新增、修改和删除的受管理文件，并显示文章标题与实际路径；点击文件在右侧对比上次提交与当前工作区的完整内容。对比显示每处改动及其前后各最多 3 行上下文，XML 正文则各显示最多 3 个内容块。绿色为新增内容，红色为删除内容，上下文使用普通底色。删除内容使用旧版编号，新增内容和上下文使用当前版本编号。

已有 Markdown 仅改动文件开头的空行，且 YAML front matter 的识别不受影响时，变更列表会隐藏该文件，并在提交时恢复上次提交的版本。正文内部的空行可以影响段落或代码，参与对比与提交。Git 规则和清单中的纯空行整理仍会在提交时还原。

XML 文章默认保留标题、列表、引用、表格和行内样式进行正文对比，只有格式变化时也会展示修改前后的内容；可切换「查看源码」检查 XML；Markdown 和 JSON 直接按文本对比。图片与附件显示变更提示，不展示 LFS 指针。点击「刷新状态」前会保存所有窗口中的文章。提交、全部暂存、全部取消暂存、推送、拉取和刷新集中在文件列表顶部的图标工具栏，悬停可查看名称；Git 配置仍在设置中。

已有 XML 文章的暂存区和工作区只有普通顶层空段落（例如 `<p></p>`）或等价的源码变化时，变更列表会自动隐藏该文件。点击提交时，文件在工作区和暂存区恢复到上次提交的版本。整次提交只有这类变化时只还原文件。正文、样式或文档属性有实质改动时，提交保留完整的 XML。

文件右侧的「+」将当前版本暂存（Git add），「−」取消暂存；文件行显示已暂存或部分已暂存。有可见的已暂存变更时，底部按钮只提交暂存区中的快照，之后继续编辑的内容留在工作区。新增或删除文章时，应同时暂存对应的 `quiet.json`，首次选择性提交还需包含 Git LFS 规则；应用会拒绝提交不完整的文档库。

撤回图标会先要求确认，再丢弃该文件未暂存的修改，恢复到暂存区中的版本（相当于 checkout -- <文件>），已暂存内容保留。新增且未暂存的文件会被删除，新增文章也会从清单移除。如清单变更涉及新增文章，需先丢弃新增文章，再恢复清单；如清单引用的正文已被删除，需先恢复正文。文档库必需文件在首次提交前不能丢弃。丢弃后会重新载入相关文档；此操作无法撤销。

## 文件与元数据

根目录 `quiet.json` 保存文档的元数据和层级，正文固定在 `Notes/<UUID>.xml|md`。每篇文档都可以通过 `parentId` 关联到父文档。移动、重命名与移入回收站只更新 JSON。完整清单示例见 [FORMAT.md](FORMAT.md)。

克隆和拉取校验 `quiet.json` 的清单版本及远端文件路径。

初始化会写入 `.gitattributes` 和 `.gitignore`，首次提交仍由用户发起。提交包含 `quiet.json`、活动与回收站正文、`Images/`、`Files/` 和 `Drawings/` 中的资源。克隆版本 2 的文档库时会自动升级工作区，提交并推送升级后的清单和新增正文，即可在支持版本 3 的设备上继续同步。仅有自动升级改动的工作区可以直接拉取这次升级提交。

```text
Quiet.md/
├── quiet.json                 version: 3，notes / trash
├── Notes/<uuid>.xml|md        固定正文路径
├── Images/                    图片和封面
├── Files/                     文件附件
├── Drawings/                  画板源文件
├── .gitattributes             上述三个目录的 Git LFS 规则
├── .gitignore
├── .git/lfs/objects/          SHA-256 对象缓存
└── .quiet/
    ├── history/               自动快照，仅本地
    └── git-preview/           不可变历史资源预览，仅本地
```

回收站由 `quiet.json` 的 `trash` 数组记录，新删除的正文留在 `Notes/`，移入和恢复只产生清单变更。回收站文档可以只读打开，浏览子文档，查看本地快照与 Git 提交历史；历史版本也可另存副本，编辑原文或恢复历史版本前须先恢复文章。回收站没有自动过期、清空或彻底删除功能；移入和恢复均可随 Git 提交、推送与拉取同步。

清单是层级和标题的唯一来源，应与正文一起备份。XML 中保留正文上次保存时的标题，但当前显示标题及历史提交标题均按对应清单读取。

`.quiet/` 整目录由 Git 忽略，保存本机设置、缓存和自动快照。Git 提交使用显式文件集合，不运行系统的 clean / smudge 过滤器；资源写为标准 LFS 指针进入 Git 对象库，工作目录中的原图不被替换。单个资源上限 256 MiB。

初始化时保留原有 `.gitignore`、`.gitattributes` 内容并补入应用所需规则。提交只包含应用管理的文件。已有仓库沿用原分支和配置。位于其他 Git 仓库内的文档库可继续编辑，应用会提示无法初始化独立仓库。已有提交却没有 `quiet.json` 的无关仓库无法用于文档库的 Git 同步。

## 正文导入与恢复

- 手工放入 `Notes/` 的文章在扫描时采用 UUID 文件名；目录不作为虚拟层级导入。遇到 UUID 冲突拒绝覆盖，不给固定文件名追加数字。
- 拉取先验证远端路径、元数据、正文格式和 LFS 的大小 / SHA-256，再修改工作目录；写入出错时恢复文章与 Git 索引，HEAD 最后更新。未跟踪同名文件不覆盖。符号链接、可执行文件和文档库以外路径不接受。
- 拉取到一半进程被强制终止时，可能留下 `.git/quiet-apply-*` 的备份；这不是多文件原子事务，需保留该目录以人工恢复。正常错误路径会自动回滚。

文章「… → 版本历史」同时列出原有自动快照与 Git 提交。Git 提交不能在抽屉里删除或重命名；查看、另存副本和恢复沿用现有入口。历史图片按提交中的 LFS 指针加载为独立缓存；恢复或另存时写入新的资源路径，不覆盖当前图片。恢复文章只形成工作区改动，之后手动提交，不回退分支 HEAD。

Git 版本化 `Images/`、`Files/` 和 `Drawings/` 中的资源；外链、任意外部文件以及旧版本在启用 Git 之前的资源字节不在此保证内。旧自动快照继续保留，未自动转换成 Git 提交。已有笔记以往的图片变化无法从当前文件反向重建。

每张画板使用固定的图源路径，后续编辑更新同一文件。只修改图源的提交也会出现在对应笔记的 Git 版本历史中。正文撤销和本地正文快照记录画板引用，查看已保存的旧图源需要先把该版本提交到 Git。

## 实现与验证

文档引擎的 `manifest.rs`、`virtual_store.rs`、`git.rs`、`git/lfs.rs`、`git_store.rs` 不依赖 GPUI；应用层 `src/git.rs` 负责配置和后台任务，`history.rs` 复用原有历史抽屉。临时目录测试覆盖旧格式拒绝 / 重开 / 链接 / 回收站、提交历史、LFS 指针与校验、HTTP batch 上传下载确认、推送克隆拉取、分叉拒绝以及写入失败回滚，不使用真实文档库。`python3 tools/harness/git_ssh.py`（需要 Python `paramiko`）另用临时 SSH / 自签 TLS 服务器验证自定义端口、加密私钥、主机密钥拒绝、LFS CA、上传确认及推送 / 克隆 / 拉取。

协议参考：[git2 文档](https://docs.rs/git2/0.21.0/git2/)、[Git LFS Batch API](https://github.com/git-lfs/git-lfs/blob/main/docs/api/batch.md)、[Basic Transfer API](https://github.com/git-lfs/git-lfs/blob/main/docs/api/basic-transfers.md)。
