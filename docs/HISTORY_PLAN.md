# 文章历史记录方案（待实施）

后续已按 2026-11-16 的新需求实现可选 Git 模式，当前实现与使用范围以 [GIT.md](GIT.md) 为准。下文保留早期快照方案的分析，尚未实现的差异查看改进仍是后续工作。

本文是基于当前 Quiet.md 与本地 `~/code/fever` 源码的功能方案，不代表以下改进已经实现。现有格式以 FORMAT.md 为准，界面样式以代码里的 Theme token 为准。

## 结论

在已有版本历史上完善，不重新做一套。沿用 Quiet.md 的本地完整正文快照；借鉴 Fever 的「右侧历史列表 + 正文区只读差异 / 文章预览」。优先补齐安全恢复、完整差异和查看状态隔离。

版本历史与撤销分开：撤销处理本次编辑步骤；历史记录跨关闭、重启保留文章的阶段版本。当前阶段不引入 Git、提交、分支和远程仓库配置。

## 保存规则

1. 正文沿用现有自动保存。历史的失败独立显示，不能阻止普通正文保存。
2. 自动版本沿用至少 5 分钟的间隔和「保存前正文」语义，保持现有快照可读；没有新保存时不靠空转定时器生成相同内容。
3. 切换文章、关闭窗口和退出前，在正文保存成功后，对本次确实编辑过的文章补存最终正文。与最新快照相同则跳过，避免短编辑会话只留下编辑前内容。连续编辑产生的中间状态仍按 5 分钟节流。
4. 「保存当前版本」立即保存磁盘上的当前正文，不受 5 分钟限制。即使正在查看历史，保存对象也只能是当前文章；反馈应明确这一点。
5. 内容相同不生成重复快照。新接口返回 `Created(version)` 或 `Unchanged`，不能通过前后文件数量判断是否新增：达到保留上限后新增与淘汰会使数量不变。
6. 时间标记称为「记录时间」。已有文件名记录的是快照生成时间，不应推断成那份旧正文最初写成的时间。

文章重命名和移动不改变历史归属，继续按文章 id 索引。回收站仍携带历史，恢复文章时一起带回；永久删除文章时一起清除。

## 存储与保留

第一阶段保留现有布局和文件名，不改原文快照、不重新序列化旧文件：

```text
.quiet/
  history/<document-id>/
    <milliseconds>-<random>.xml   # 或 .md，完整正文
    <milliseconds>-<random>.xml.name
  history-trash/<document-id>/
    ...
```

继续用原子写入，目录就是历史索引，避免依赖一个容易冲突的全库 manifest。名称仍用已有 `.name` 文件。

建议将设置里的 1–30 份解释为「自动版本保留数」，默认 20；命名版本与恢复保护版本不计入自动淘汰数。命名版本每篇另限 30 份，达到时提示先取消命名或删除，不静默丢弃里程碑。恢复保护版本至少保留最新一份，成功恢复后旧保护版本可按普通自动版本淘汰。

200 MiB 作为正文历史预算，统计活动文章及回收站历史。先清理最旧的普通自动版本；命名版本和最新恢复保护版本不能为新自动版本让位。仍无空间时停止新增自动历史并显示可操作的提示，正文照常保存；手动保存与恢复保护若无法落盘，明确返回失败。大于预算的单份正文同样报告历史不可保存，不能写入后又立即删掉。

要区分恢复保护版本，后续可增加与快照同名的 `.meta.json`，先只记 `reason`（automatic / manual / before_restore）与 `origin_rel`（记录时的文章相对路径）。缺失时按旧快照读取；命名仍以 `.name` 为准。`origin_rel` 用于解释历史相对链接，不能直接当作任意磁盘读取权限。

这类附加文件不改变文章与主索引的含义，按当前兼容规则不需要提升 FORMAT；实施前仍需核对旧版本扫描、清理和迁移行为。旧版本不会执行新的保护保留策略，不能承诺降级使用时命名版本仍受保护。

## 查看方式

保留文章「… → 版本历史」入口和右侧抽屉。打开时先显示当前文章与版本列表，不自动切换到旧正文；用户点击某一版后进入只读历史状态。

```text
正文区                                    右侧：版本历史
正在查看 11 月 15 日 14:30 · 只读             当前版本
[显示改动] [预览此版本]                     今天
[返回当前] [恢复此版本]                       14:30 投稿前  +12 −3
                                           14:05         +4 −1
上一份保留版本 → 所选版本                    昨天
  相同段落                                   21:10 初稿
− 被删除的句子
+ 新增的句子                               [保存当前版本]
                                           [另存副本] [删除此版本]
```

- **显示改动**：选中历史版本后默认进入此模式。展示「上一份保留版本 → 所选版本」，删除和新增都能看到，保留完整上下文；前后文较长时允许收起相同内容，并可展开。用 Theme 现有语义色并同时显示 `+` / `−`，不能只靠颜色区分。
- **预览此版本**：复用当前只读文章渲染，展示标题、段落、表格、图片等原有结构。保留现有「显示改动」能力，其块级着色只作为辅助提示。
- **对比基准**：默认上一份保留版本，明确告诉用户中间自动版本可能已淘汰；可切到「与当前版本比较」，此时固定标明「所选历史 → 当前」。更晚阶段再做任意两版比较。
- **最早版本**：显示「没有更早的保留版本」，只提供全文预览和与当前对比；不假装它是文章创建版本，也不把全文标成新增。
- **空历史**：保留现有空状态与保存按钮，不生成假的历史条目。「当前版本」是实时入口，不计入历史数量。
- **退出**：返回当前后恢复编辑状态，抽屉可继续保留；关闭抽屉或切换文章同样退出历史。Esc 先退出预览，再关闭抽屉，沿用现有行为。
- **操作**：保留命名、仅看命名、另存副本、删除。取消命名编辑不得清空原名称；删除成功后可短暂撤销。另存副本保留来源时间或名称作为标题后缀。

差异按用户能理解的文档结构生成：XML 先解析成块，再比较文本与可见属性，不展示 XML 标签。首期覆盖正文与标题文本、新增 / 删除块；纯样式、勾选、表格与媒体属性变化要给出明确的「格式 / 属性变化」摘要，不能显示成「无变化」。Markdown 按原始文本比较，同时保留文章预览。

## 状态隔离与安全恢复

当前通过把历史正文装入同一个 Editor、保存原 Core 来预览。发送端虽然跳过同步，但接收端仍可能把其他窗口的当前正文送入历史预览。因此建议正文编辑器与历史展示实体分开：当前 Editor 始终保留活文档，历史渲染只使用独立只读 Editor / diff 列表。

当前编辑器在历史模式下从界面和输入焦点中移开，不接受用户编辑，仍接收同文章窗口的更新。返回时恢复光标、选区、滚动位置和撤销状态；若另一窗口修改了正文，按现有实时同步规则呈现最新内容，不能将进入历史前的旧副本覆盖回去。差异基准若为当前版本，则标记其变化并重新计算。

恢复流程由 Store 在同一个写锁内协调：

1. 先正常保存当前文章；失败则沿用现有保存失败处理，不继续恢复。
2. 读取并验证所选历史内容，核对当前磁盘内容与加载基线，保留现有多实例冲突检测。
3. 强制保存恢复前正文，并确认该快照可用、不会被本次裁剪淘汰。保护快照失败时终止恢复。
4. 走现有正文保存路径写入所选历史；不改文章 id、文件夹、收藏等管理属性。沿用当前标题跟随文件名的规则；Markdown 标题仍由文件名决定。
5. 保存成功再退出历史并同步其他窗口。正文或索引部分成功、后续失败时沿用真实保存结果与恢复错误流程，不能一概提示「当前版本未被改动」。

恢复后的退路是历史里的「恢复前版本」；初期不额外承诺 Cmd+Z 可跨恢复回退。若未来将恢复加入编辑撤销，必须经 Core 方法实现并补 fuzz 随机操作。

## 性能与内容边界

- 打开抽屉先列目录和名称，不在 UI 线程逐对解析整篇文章。差异与统计在后台按选中版本或可见列表项计算，并缓存结果。
- 请求绑定文章 id、版本名、比较基准和递增请求号；快速切换文章 / 版本后，旧结果不能覆盖当前界面。
- 差异算法设置明确的内存和计算预算。超限退回两份完整正文的虚拟列表或分页阅读，并标明「未计算完整差异」；不能静默只比较前 1,200 行，也不能把未完成计数显示为精确的 `+N −M`。
- 第一阶段是正文历史。内嵌在正文中的资源数据随正文保存；外部文件和可被覆盖的附件路径不保证历史字节可恢复，缺失时给出占位和说明。「不清理 .assets」不能代替附件版本化。
- 下一阶段借鉴 Fever 的历史图片原理，为应用管理的图片 / 附件按内容哈希保存不可变对象，快照记录引用关系，恢复时重建引用；预算需要把资源字节计入。外链网页及文章之外的任意文件不纳入首期承诺。
- 已有历史没有记录原路径，文章移动后某些历史相对链接可能无法还原。新元数据可改善后续记录，不能推断并伪造旧版本的路径或 Markdown 旧标题。

## 实施顺序与验收

**第一步：可靠性。** 修复手动保存用数量判断结果、取消命名却清空名称、打开历史忽略 flush 失败，以及恢复保护失败被忽略的问题。把恢复协调收口到 Store，覆盖冲突与失败路径；再实现命名 / 恢复保护保留规则。

**第二步：查看体验。** 分离当前编辑器与历史展示实体；补全差异 / 文章预览两种模式、删除内容展示、后台计算与大文章降级。沿用现有入口、Theme 与快捷键。

**第三步：历史完整性。** 补存结束编辑时的最终状态、记录快照来源与原路径，处理历史链接解析；附件不可变对象存储另作一项完整改动。文章 id 在索引重建后与旧快照失联属于现有问题，后续需单独设计稳定身份恢复。

验收至少覆盖：

- XML / Markdown 自动保存、短编辑会话结束、手动保存、内容去重、应用重启后的历史读取。
- 保留数满后仍准确报告新增；命名版本受保护；预算不足不阻止正文保存；回收站历史计入预算。
- 预览期间输入、粘贴、拖放不改历史；另一窗口编辑不污染历史，也不会在返回时丢失当前内容。
- 恢复前快照写入失败、所选版本损坏、磁盘外部修改、正文写入或索引写入失败时结果准确、内容可追回。
- 删除段落、纯样式变化、最早保留版、超过 1,200 行且改动在末尾、百万字文章及快速切换版本。
- 取消命名不修改原名称，删除可撤销，重命名 / 移动 / 回收站恢复后历史仍对应同篇文章。

存储测试全部使用临时目录；UI 验证用 `QUIET_MD_HOME` 和现有 harness。功能实现后运行 `scripts/check.sh`；若改编辑内核，按仓库约定补 fuzz 并运行 2,000 个种子。本轮仅编写方案，不修改功能代码或真实文档库。
